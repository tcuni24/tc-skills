# 实例：同一客户的草莓与香菜 SSR 方法说明（2026-11-09）

两份交付属于同一客户，分析方法不同：

| | 草莓 | 香菜（TC-WGS-20260920-ZDQ001） |
|---|---|---|
| 思路 | 以红颜（Benihoppe）基因组为参考，侧翼锚点比对 6 个品种的公开组装，比较重复次数 | 10 份材料重测序，HipSTR 联合分型，按 9 个标记位置筛选候选 |
| 交付 | 10,587 个多态候选位点，`polymorphic_SSRs_amplicon_sizes.xlsx/.tsv` | 27 对候选引物，`SSR候选标记_含各样本扩增产物大小.xlsx` |
| 生成脚本 | `amplicon_v2/make_deliverables.py`（xlsx + docx） | `scripts/add_amplicon_sizes.py`（xlsx，有测试）+ `scripts/build_methods_docx.py` |

用户要求：交付前审核，两个分析方法不同，但说明的共通部分要统一。

## 发现的问题与处理

| 问题 | 处理 |
|---|---|
| 香菜封面残留「文中黄色高亮部分为待核对信息」 | 删除 |
| 草莓特异性判据写成「全长精确命中」，脚本实际是「100% 一致且比对长度 ≥ 18 bp」 | 按脚本改；香菜脚本核对后确为全长，保留 |
| 香菜 Primer3 参数表把 Tm 写成「退火温度」 | 改为「引物 Tm」 |
| 香菜「客户提供的样品」「如客户的前后 20% 是指……请告知」 | 改为「送检材料」；窗口定义的询问移到「使用建议」 |
| 香菜漏斗用了较早中间表的 13,869 / 916 | 按交付 README 改为 14,785 → 14,725（去掉重复次数层面无差异的 60 个）→ 13,813 带引物（912 个无引物）→ 13,806（去掉 8 个负值，其中 1 个本身无引物）；特异 6,073 |
| 曾推算出「剔除 63 个负值位点」，查不到来源 | 删除该数字，不编 |
| 香菜写了 GPU 型号、`genome.fa`、`LB=lib1` / `PL=ILLUMINA`（测序平台实为 DNBSEQ）、HipSTR 命令里的内部文件名、16 线程 | 用户指出 GPU 型号与 `genome.fa` 后，全文排查同类问题一并删除 |
| 草莓写了内部脚本名、`-outfmt` 字段串、`-num_threads` | 删除 |
| 两份章节结构不同；草莓缺参考文献与交付文件表，香菜缺字段说明表与更新附录，香菜表格无编号 | 按统一骨架补齐；版式代码两边逐字一致（diff 校验），表题自动编号 |
| 草莓中文句中用半角标点；范围符号与百分比位数不一 | 全角标点、「–」、1 位小数 |
| 草莓文件名「草莓SSR筛选方法说明.docx」 | 改为「草莓SSR标记开发方法与结果说明.docx」，xlsx 说明页中的引用同步改 |
| 香菜新增页用中文列名，与草莓不一致 | 改为与草莓同一套英文列名（`ref_size_bp`、`YS01_size_bp`…、`size_min_bp`…），补 `size_diff_bp`；列说明 `COLS` 一处维护，docx 字段表 import 同一份 |

## 交给用户决定的事

- 草莓重复次数按参考方向校正后，10,587 个候选中只有 8,345 个（78.8%）仍满足多态判据。
  用户答复「按实际交付的分析结果来」：集合保持 10,587 个，文中如实写 8,345，结果表加 `repeat_polymorphic` 列标注。
- 缺失值写法（草莓留空 / 香菜 NA）、特异性写法（特异 / Specific）、xlsx 文件名风格：用户未要求，未改，汇报中列出。

## 验证

- 香菜 xlsx 脚本先补测试看到红灯，再改列名转绿（10 项）；新表除新增列外与改名前逐格一致；草莓数据页与备份逐格一致。
- 两份 docx 用 pandoc 转文本复读；`check_methods_doc.py` 新版 ERROR 为 0，旧版报出上述内部信息；`--compare` 对照章节结构。
